# Discipline Rules

A discipline rule governs an action the agent knows but skips under pressure.
Apply this reference only to that rule, not to unrelated output formatting.
Pressure checks belong to the core's check batch; the permitted edit belongs to its fix round. This reference grants no additional rounds.

## 1. State the protected action

Put the rule beside the action it governs in the core skill.
Name the observable completion evidence before the next action can occur.
Use a named stop condition for missing evidence.
If a lived failure contains an excuse, preserve that excuse verbatim in the authoring record.
Done when the draft names the action, required evidence, and stop condition beside the governed action.

## 2. Run 2 pressure cases

Use 2 fresh sessions with concrete inputs and a decision that requires action.
Combine at least 3 pressures per case: time pressure, sunk cost, and an authority requesting a shortcut.
Require the correct authorized action; explaining the rule without acting fails the case.
If authorization is absent, the correct action is to stop the unauthorized step.
Quote the action evidence and any observed excuse.
Pass means the correct action occurs in 2 of 2 pressure runs.
Done when both cases have action evidence and pass/fail verdicts.

## 3. Apply at most 1 edit

If both runs pass, retain the rule and stop pressure testing.
If a run fails and global budget remains, make 1 edit to the protected rule.
For a missed instruction, move the rule beside the action; for an ambiguous instruction, state the required evidence explicitly.
Use an excuse table only for verbatim observed excuses; keep at most 8 rows.
Each row pairs the observed excuse with the required action and evidence.
If more than 8 distinct excuses occur, hand off the overflow as evidence instead of enlarging the table.
After the edit, rerun the 2 pressure cases once within the remaining global budget.
If the rerun fails, automate the rule with a script, hook, or validator when authorized; otherwise escalate with evidence.
If the budget ends earlier, escalate immediately.
Automation does not authorize another fix round or check batch.
Done when both cases pass, automation enforces the rule, or the human receives the failed cases and unresolved rule.
